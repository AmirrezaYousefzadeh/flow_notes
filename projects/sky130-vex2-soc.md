## sky130 items (audit of 2026-10-24)

**The published power numbers of this project are probably 25–55 % low** (issue 1). Ask the owner before rerunning

### 1. Clock-propagation stop removes most of the combinational power (notes 8.2)
- `power/power_pin_sta.tcl:14-18` applies `set_clock_sense -stop_propagation` at the 3 `dlclkp` outputs, with
  toggle-count activities. `u_sleep.u_core_icg.u_icg` gates `clk` into `core_clk`, which clocks the CPU, both bus
  bridges and the two SRAM gates: 1 870 of 1 880 flip-flops sit behind the stop.
- Evidence (per-instance join of `RUN/final/nl`, `power_pin_by_instance.rpt` and `activity.tcl`, read-only):
  in `out_pin_mnist_decode` only about 2 300 of 15 700 logic cells get any power; 9 615 combinational cells with
  measured output activity above 10⁻³ per cycle report 0 W (for example `_11997_`, activity 0.30, 0 W); 1 850 of
  1 869 `dlygate` hold cells report 0. About 80 % of the measured logic activity sits on zeroed cells. Flip-flops and
  the clock tree are unaffected.
- Rough effect: combinational 3–5× higher (5–8 mW instead of 1.6 mW in the decode window), running totals 25–55 %
  low. Sleep numbers (0.076–0.077 mW) are barely affected.
- Fix: remove the stop; rerun OpenSTA on the same toggle files (no new simulation needed) and compare per group.
- Affected: `docs/results/mnist_pin_energy.txt`, `docs/results/nmnist_pin_energy.txt`, `README.md:36-38,70-72,76-80`,
  `firmware/nmnist/README.md:91-94,110,114`, and the Async_inference memory note on the vex2 workload. They also lack
  the SRAM read-energy correction (FLOW_ISSUES 1.1).
- **`FLOW_ISSUES_FROM_NEAT.md` 1.6 compares the wrong numbers:** the 54.6 % combinational share is from
  `out_waveform_gls_nmnist/power_sleep.rpt`; the awake report of the same run gives 4.6 %. The legacy global-activity
  flow is not a cross-check (notes 8.7): its "within 5 %" agreement comes from cancelling errors.

### 2. Power grid (notes 9.1, 5.2)
- Every run has 545 812–547 620 power-grid violations (`final/metrics.json`), hidden by
  `ERROR_ON_PDN_VIOLATIONS: false`. `pdn_cfg_sram22.tcl:93-99` connects met4/met5, met3-met4 and met2-met3 but lacks
  NEAT's `add_pdn_connect -grid macro -layers "met2 met4"`. FLOW_ISSUES 2.10 calls this repository's PDN the
  reference; it is not. Use NEAT's `pdn_cfg_sram22.tcl`.

### 3. SRAM22 clock slew and the clock gate wrapper (notes 3, 9.1)
- A `dlclkp_2` drives each SRAM clock directly (`rtl/soc/clk_gate.v:11-12`): `u_imem/clk` 1.99 ns and `u_dmem/clk`
  1.66 ns against a 0.351 ns limit, `u_imem_icg/GCLK` 1.48 ns against 0.75 ns (`checks.rpt`). This is a real violation,
  unlike the `dout` slews. Buffer the macro clocks.
- The `clk_gate` wrapper produces the 3 SDF errors; instantiate `dlclkp` directly or rename (notes 5.4).

### 4. Constraints and sign-off (notes 6)
- `sky130_vex2_soc.sdc:71-77`: the five sleep-flop exceptions match nothing (only nets keep the names after
  flattening; the SDC uses `/`, the flat names `.`). Also `set_false_path -from [get_ports wake]` (`:66`). Count
  matched objects and fail at zero.
- Hold WNS +0.048 ns comes from OpenLane's sign-off, not an own OpenSTA sign-off (acceptable for a flat netlist with
  zero SPEF misses, but state it).

### 5. Simulation and power-script details
- `run_gls.sh:248-251` prints the SDF error count but never fails.
- Annotated runs use the zero-delay SRAM model (`rtl/sram/sram22_2048x32m8w8.v:55`), not a `_tdout` model.
- `power_pin_sta.tcl:7` reads the SRAM liberty only "if the file exists" (notes 8.3): fail instead.
- `power_pin_sta.tcl:32` calls `report_activity_annotation`, which does not exist in OpenSTA 2.6.0: the coverage
  check is dead.
- `out_waveform_gls_nmnist/power_energy.txt` says "10 ns TB period"; the testbench uses 20 ns (`tb_fw_nmnist.v:21`).

### 6. Library and fill (notes 9.4, 5.1)
- The design uses `sky130_fd_sc_ms`, whose liberty has zero leakage for every cell, and no `diode_2` (14 506 diodes
  black-boxed). Reported leakage is the macros' only. Say so with every leakage or total-energy number, or decide with
  the owner whether to move to `hd`.
- Decap fill on, heuristic diodes on, hold margin 0.1 ns, `GRT_ALLOW_CONGESTION: true` (`config.yaml`): document
  these as deliberate or align with notes 5.1.
